# Process Performance (PPERF) - process application

Where the time goes: duration statistics per activity (average, median, P95, max from the closed tasks of the last N days), per process (completed instances, creation to last change), throughput per day (instances started / completed / failed / terminated, as a table per application and an SVG bar chart), and the observed variants of every process (the ordered sequence of user tasks of each completed instance and how often each sequence occurs). The engine's own performance endpoints (`/performance/query`, `/performance/instance/{id}`) need tracking groups and are not used.

Package `Process-Performance-1.0.twx` (generated by `tools/build_pperf.py` on twxkit + kitlib, standard library only, no base export); targets: 8.6.2, BAW 20-26 (classic v1 API).
Vanilla BAW: UI Toolkit controls only, one client-side human service, server-side service flows calling the REST API (and, where no
API exists, the product database read-only through the engine's datasource) with the technical user of the environment variables.

## Dashboard

| Tab | Content |
|---|---|
| Step durations | application, process, last N days, Compute, Export CSV; table per activity |
| Instance durations | table per process |
| Throughput | SVG bars per day + table per day and application |
| Variants | table of activity sequences with share |

Every list has a status line; errors open a message modal; CSV export shows the text in a modal for copy / paste.

## Service flows, REST calls and SQL

| Flow | Does |
|---|---|
| PP Step Durations | `PUT /search/query` byTask `taskStatus|Equals|Closed`, `taskClosedDate|GreaterThan|<since>` [+ application, process], columns taskReceivedDate / taskClosedDate / taskActivityName -> statistics per application / process / activity (newest 500 closed tasks) |
| PP Instance Durations | byInstance `instanceStatus|Equals|Completed`, `instanceModifyDate|GreaterThan|<since>` -> statistics per process (rows de-duplicated by instanceId) |
| PP Throughput | byInstance `instanceCreateDate|GreaterThan|<since>` (started) and one query per final status on `instanceModifyDate` -> per day, SVG |
| PP Variants | byTask closed tasks of completed instances -> ordered activity names per instance -> variant counts and share per process |
| PP Rows To CSV | step rows -> CSV |

Verified: 8.6.2.20001 lab: 500 closed tasks of 120 days in 6 activities with statistics; 10 processes with instance durations; throughput of 30 days (500 started, per-day rows, 7.6 KB SVG); 487 completed instances in 11 task-level variants. Dashboard playback: no JavaScript error, no failed call.

## Pitfalls met

* The search answers at most 500 rows per query: statistics cover the newest 500 closed tasks / instances of the period - narrow the period or the application for exact numbers.
* Instance duration ends at `instanceModifyDate` (the search has no close date column); a completed instance touched later shows a longer duration.
* Variants are task-level only: system activities, scripts and gateways leave no task, so two paths that differ only in system steps look the same.
* Both performance endpoints of the v1 API answer CWTBG0019E "Couldn't find the tracking group" unless the process defines tracking groups - they are not a general source.
